# Security and Privacy

This is a static data, Bible-study, and offline-demo project. It does not require accounts, analytics, remote scripts, or secrets.

## Reporting a sensitive issue

Do not open a public issue containing a password, token, private key, personal record, or other sensitive information. Use GitHub's **Private vulnerability reporting** feature from the repository's Security tab. If that feature is not enabled yet, notify the maintainer without including the sensitive value and wait for a private channel.

For ordinary content corrections, broken links, and classification questions, a normal public issue is appropriate.

## Before contributing

- Assume every committed file will remain public permanently.
- Remove personal journals, private prayer requests, names, addresses, phone numbers, and email addresses unless the people involved explicitly consented to publication.
- Never commit `.env` files, passwords, access tokens, private keys, recovery codes, or account exports.
- Do not commit Obsidian workspace/session state or trash folders.
- Check document properties and image metadata before adding office files, PDFs, photographs, or screenshots.
- Review staged changes before every commit.

The `.gitignore` blocks common secret and private-note locations, but it is a safety net—not a substitute for review.
